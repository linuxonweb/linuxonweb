# Proposed startup-class rebase and compile controls

This is a source and execution plan. No startup-admitted compiler or genuine
owner module has passed runtime acceptance.

Producer31 publishes the same GNUFrames.cpp and WebAssembly.h bytes as the
producer27 basis used for proposal1. Its separate FrameLowering.cpp correction
materializes actual record/context frame indices in the true prologue. A fresh
proposal must retain producer31's source pair and apply only the independently
reviewed startup delta. It must not substitute the older target archive or
change the corrected frame-index capture. The EH consumer adds only a distinct
authenticated startup query; the primitive2 query remains unchanged.

Before any compiler rebuild, pin the coherent consumer's actual source files,
target archive members, executable, headers, normal ABI controls and current
failure. Recheck the proposed pair against that exact basis. Record source and
archive differences by member occurrence, retaining duplicate basenames. Build
only changed translation units into a new owned archive and fresh executable;
preserve the original archive and all earlier failed controls. Use a separate
bounded task with disk reserve checks and owned-PGID cleanup.

The first compile controls use actual linked early owner IR and an independently
inspected exact manifest. The manifest's module/body/type/call seals must be
computed before any compiler transformation. Authenticated class8 covers only
the reviewed block/prepare/TP bootstrap closure; root getter and stack-free
admission remain class2, owner gate/restore and GNU helpers remain class4.

Required positive evidence is:

- Ordinary class2/class4 inputs retain their existing behavior and the separate
  primitive query never returns true for class8.
- Exact startup calls emit no record publication, poll, linear stack frame,
  stack-pointer write, or EH guard. Inspect actual assembly and final bodies.
- The same module's owner gate, restore, GNU signal and unwind helpers publish
  real records. The live caller contains the actual GNU cancellation anchor.
- The actual linked root points at the compiler's descriptor table; startup8
  functions are absent from that runtime table. Root generation and worker
  task/instance epoch remain distinct.
- The final entry assembly, linker TLS initializer and getter are bound to
  inspected native bodies with their actual arguments and order. Independently
  check every referenced final-body audit, not only its SHA field length.

Meaningful fail-closed compile controls change one authentic input at a time:
source-supplied startup seal; class8 under manifest version1; changed call
operand/order; missing or extra call; forged external type/import name; missing
assembly artifact; linear alloca or TLS operand before initialization; indirect
startup call; class4 call or escaped pointer to startup8; constructor list;
altered module/body hash. They must fail before producing an admitted object.
Final object controls additionally reject a Wasm start section, unsealed TLS
initializer body, wrong final-body proof, unexpected bootstrap import, and an
unrecorded restore or handler.

Constructor rejection is a finite diagnostic limitation. Future Nightly
initializers must execute as descriptor4 after owner publication with separately
proven loader ordering; no constructor is discarded or interpreted as class8.

The executable owner command cannot yet name a passed final manifest. The
remaining artifacts are: composed compiler with startup/EH query acceptance;
actual ordered early GNU/bridge/provider IR list and exact class2/4/8 manifest;
strict recorded module link resolving genuine GNU unwind/abort/jump definitions;
final entry/TLS/import/no-start seals; and actual worker single-use phase guards.
Only then can the owned candidate kernel and full regression runner execute the
ordinary owner gate, followed by real blocked cancellation and child startup.
Normal compile success or synthetic phase callbacks do not replace those gates.
