# Zink B2f: generic buffers, suballocation, gate B GL strings and glClear (2026-10-01)

Packet goal: make the guest Vulkan ICD carry Mesa 26.2.3 Zink further.
Result: **partial, gate B advanced well past B2e.**

- `eglCreateContext` now succeeds for ES 2.0 and GL 2.0 compat, and
  `eglMakeCurrent` works surfaceless.
- The GL strings are printed.
- `glClear` plus `glReadPixels` returns exact pixels through the guest ICD
  on NVIDIA WebGPU.
- The first draw does not complete. The probe stops after the clear, before
  the first shader-compiled marker; see the blockers below.

All 20 regression suites pass on NVIDIA WebGPU and Intel WebGL2.

Task root: `/mnt/p6/build/zink-b2f-20261001/` (ext4, disk-backed).
Evidence: `docs/evidence/zink-b2f-20261001.json`. The changes are
uncommitted in the working tree; no git state was changed.

## Changes (adapter code in `web/linux/tests/`, no Mesa edits)

All new behaviour is gated by `GUEST_VK_ZINK`. Only the zinkcaps build and
the gate-B link define it, so every other suite keeps its old behaviour (the
counts below are identical to B2e).

### `guest-vulkan/transfer.inc`

**Generic buffer model.**
- Under ZINK, `vkCreateBuffer` accepts any usage combination.
- The exception is a legacy buffer: one bounded role and 64 KiB or less. It
  keeps the old single-role path and the old requirements (alignment 4, one
  memory type).
- Generic buffers report size rounded up to 256, alignment 256 and
  memoryTypeBits 3.
- Their bytes stay guest-side in the bound memory. Host buffers are created
  lazily by the role that consumes them.

**Memory suballocation.**
- The heap is 256 MiB under ZINK (`GUEST_VK_HEAP_BYTES`), and one allocation
  may be as large as the heap.
- `vkBindBufferMemory` and `vkBindImageMemory` accept nonzero aligned
  offsets, so many resources can share one `VkDeviceMemory`.
- Memory bytes are allocated lazily.
- `vkMapMemory` works on type 0 and type 1 at any in-range offset.

**Command recording.**
- Multiple command pools and buffers per device (`SELECT_CB` per recording
  call).
- Lenient barriers: only layout transitions are recorded; generic-buffer
  barriers are no-ops.
- `vkCmdCopyImageToBuffer` accepts a sub-rectangle region into a generic
  buffer at a buffer offset. This is what Zink's `glReadPixels` path uses.

**Zink colour images.**
- Accepted with usage 0x97 (TRANSFER_SRC|DST, SAMPLED, COLOR_ATTACHMENT,
  INPUT_ATTACHMENT), the MUTABLE_FORMAT/EXTENDED_USAGE flags and a
  `VkImageFormatListCreateInfo` chain.
- Layout rules are relaxed for these images.

**Core 1.0/1.1 entry points.**
- `zink-stubs.inc` (new, generated by `gen-zink-stubs.py`) supplies typed
  stubs that trace and fail, for every core 1.0/1.1 command the ICD does not
  implement.
- Zink resolves all of them at apiVersion 1.1. A NULL pointer, or a call
  through a mismatched `void()` stub, traps or hangs in wasm.

### Other ICD files

- `guest-vulkan/zink.inc`: real implementations of:
  - `vkFlush`/`vkInvalidateMappedMemoryRanges` (no-op, because bytes are
    read at submit);
  - pipeline caches (empty);
  - `vkGet{Buffer,Image}MemoryRequirements2`, with dedicated allocation
    reported as not preferred and not required;
  - `vkBind{Buffer,Image}Memory2`;
  - `vkGetDeviceMemoryCommitment`;
  - `vkGetDescriptorSetLayoutSupport`, answered by trying the bounded
    create.

  It also adds the `begin_rendering` trace and `SELECT_CB` on dynamic
  rendering.
- `guest-vulkan/icd.c`:
  - `zink_color_usage_ok` and the matching image-format-properties
    relaxation;
  - `GUEST_VK_TRACE_CALLS=1` per-call tracing;
  - device-proc fallback to the stubs, with a trace on MISS.
- `guest-vulkan/compute.inc`:
  - descriptor pools accept Zink's shape (several types, several sets);
  - storage upload and readback honour the buffer's memory offset.
- `guest-vulkan/uniform.inc`:
  - stage mask accepts ALL_GRAPHICS|COMPUTE under ZINK;
  - wider `UNIFORM_SET_BINDINGS`.
- `guest-vulkan/texture.inc` and `graphics-commands.inc` honour the buffer
  memory offset (`m->bytes + b->offset`). `graphics-commands.inc` also adds
  `SELECT_CB`.
- `guest-vulkan/wsi.inc`: the swapchain allocation limit uses
  `GUEST_VK_HEAP_BYTES`.

### Build and test files

- `guest-vulkan-graphics/build.py`: `guest-vulkan/zink-stubs.inc` added to
  the frozen source list. Without it the zinkcaps compile fails; see the
  failed runs below.
- `guest-vulkan{,-graphics,-compute,-loader}/storage.py`: task root added to
  the storage guards.
- `guest-vulkan-zinkcaps/client.c` and `guest.html`: new B2f round 12 (see
  below). The expected host counters are now 12 passes, 14 draws, 11
  uploads, 6 uniform uploads and 13 readbacks; the observed values match.

## zinkcaps B2f round (both backends)

**Buffers.**
- 1000-byte buffer with usage 0x1ff reports requirements 1024 / 256 /
  types 3.
- 70000-byte TRANSFER_SRC|DST buffer reports 70144 / 256 / 3.
- 512-byte VERTEX|INDEX buffer is created.
- 64-byte legacy TRANSFER_DST buffer keeps the legacy requirements 64 / 4 /
  type 2.
- A 512 MiB buffer is refused.

**Suballocation.**
- 135,168-byte allocation (type 1).
- Binding is refused when misaligned (offset 100), past the end, or when the
  buffer is already bound.
- Two buffers bind at offsets 768 and 2048.
- A second allocation (type 0) takes the vertex/index buffer at 512.

**Mapping at offsets.**
- Map at 512 and write; then a whole-memory map sees exactly bytes
  [512,1024).
- Mapping at the end offset is refused.
- Map at 2048 and fill 70,144 bytes with 0x5a; a whole map verifies it.

**Other checks.**
- Zink-shaped descriptor pool {UB 24, CIS 8, SB 4} with maxSets 8 succeeds;
  a pool with a zero count is refused.
- A Zink colour image (usage 0x97, MUTABLE, format list) passes both the
  format-properties query and `vkCreateImage`.

**Frame.**
1. Clear-only dynamic-rendering pass (red), which is the shape of Zink's
   glClear.
2. Barrier to TRANSFER_SRC.
3. 8x4 sub-rectangle copy from (4,2) into the generic buffer at
   bufferOffset 256, plus the full legacy readback.
4. Every byte of the 70,144-byte suballocated range is verified: the region
   is red, the rest stays 0x5a, and bytes [0,2048) stay zero.

GUEST_VK_ZINKCAPS_PASS frames=12

**What the clear does.**
- glClear is lazy in Zink. The read map flushes it as `vkCmdBeginRendering`
  with `loadOp=CLEAR` (blue 0,0,1,1) on a 32x32 BGRA/RGBA FBO.
- The readback is a region copy into a suballocated generic buffer.
- Pixels 4 and 28 read back as 0,0,255,255.

**Where it stops.**
- After the CLEAR line, neither run prints anything more (no `STEP <mode>
  compiled`) until the page timeout.
- So the draw section stalls inside `glCreateShader`/`glCompileShader`, or in
  GLSL-to-NIR-to-SPIR-V work before the first marker.
- No Vulkan call is traced after the clear's last `vkBeginCommandBuffer`.
  The stall is therefore CPU-side in Mesa, or in an untraced 1.2/1.3 entry
  point (`GUEST_VK_TRACE_CALLS` only wraps the 1.0/1.1 names).
- Push constants (B2c) are still required before any Zink draw can execute.

Zink still warns at startup:

```
WARNING: ... doesn't support base Zink requirements: feats.features.logicOp scalarBlockLayout OR EXT_scalar_block_layout have_EXT_custom_border_color have_EXT_line_rasterization
```

## Failed runs (preserved)

- `build-run1` / rebuild-all run1: the zinkcaps compile failed with
  `transfer.inc: fatal error: 'zink-stubs.inc' file not found`, because the
  new file was not in the frozen list. Fixed in `guest-vulkan-graphics/build.py`;
  build/package run2.
- `zinkb/guest-webgpu-run1`, `run2`, `run8`: eglCreateContext 0x3003 during
  bring-up of buffers, descriptors and memory. run2 traces
  `set_layout REJECT binding=5 type=6 count=1 stages=0x20`, which led to the
  uniform stage-mask relaxation.
- `run3`: `ZINK: vkCreateCommandPool failed`, which led to multiple command
  pools/buffers per device.
- `run5`-`run7`, `run9`, `run10`: no CTX line before the timeout. These are
  hangs during context creation on NULL or mismatched core procs; run10's
  last traced call is `vkAllocateCommandBuffers`. Fixed with the typed stubs
  and the real entry points in `zink.inc`.
- `run11`: `ZINK: vkCreateDescriptorPool failed`, which made the framebuffer
  incomplete (GL_INVALID_FRAMEBUFFER_OPERATION 0x506 in glClear and
  glReadPixels). Fixed by the Zink pool shape.
- `run13`: CLEAR fails because create_image rejects the format-list pNext
  and usage 0x97.
- `run14`: `end_command REJECT state=4`, a strict barrier; fixed by the
  lenient barriers.
- `run15`: first CLEAR PASS.
- run16 and run17 are the reference runs above. They are recorded as
  `pass=false` only because the draw does not finish.

## Remaining blockers, in order

1. **Draw path stalls before shader compile completes.**
   - Next step: add 1.2/1.3 entry points to the call trace and STEP markers
     inside compile, or run the probe with `NIR_DEBUG`/`ZINK_DEBUG=spirv` to
     see whether NIR-to-SPIR-V finishes.
   - Then B2c push constants (Zink's draw path needs them).
2. **Commands that are still stubs.**
   - `vkCmdSetViewport`/`vkCmdSetScissor` as dynamic state.
   - `vkCmdCopyBuffer`, `vkCmdFillBuffer`, `vkCmdUpdateBuffer`.
   - Query pools.
3. **Generic buffers as draw inputs.** Generic buffers hold bytes and serve
   copies, but are not yet bound as vertex, index or uniform sources for host
   draws. Lazy per-role host buffers at submit are still to do.
4. **Reported allocation limit.** `maxMemoryAllocationSize` is still
   reported as 1 MiB, although allocations up to 256 MiB are accepted under
   ZINK (zinkcaps checks the 1 MiB value).
5. **Thread safety.** `GALLIUM_THREAD=0` is required.
6. **Base Zink requirements.** Still missing: logicOp, scalarBlockLayout,
   custom_border_color, line_rasterization.
7. **WebGL-class limits.** The host limit of 128 for textures and render
   targets still caps `GL_MAX_TEXTURE_SIZE` at 128; WebGL needs 2048 or more.
