# Zink B2c: first-draw stall root cause, typed stubs (2026-10-01)

Task directory: `/mnt/p6/build/zink-b2c-20261001` (ext4, disk-backed; TMPDIR/TMP/TEMP
under its `tmp`). Base `d66ae18` (B2f). Status: **stall found and fixed; Gate B
(coloured triangle) not reached**. Push constants are still not executed.
glgears with `gldriver=zink` has no FPS figure because the first draw still fails.

## 1. The stall was two silent Wasm traps, not waits

The probe printed nothing after `glClear`/`glReadPixels`. The guest did not stall
in a wait. Two `call_indirect` traps killed the guest thread. worker.js logs them
only as `[user-module] WebAssembly runtime trap`. The harness
(`zinkb/run-eglprobe.mjs`) now pauses on exceptions, samples guest stacks
(`STACK_AFTER`/`STACK_STALL` -> `stacks.json`) and records trap stacks. The new
probe `STEP` markers locate the failing GL call.

### 1a. Member-function-pointer ABI (runs 1-4, `glCompileShader`)

- **Where it trapped.** `builtin_builder::_image()` in Mesa's GLSL
  `builtin_functions.cpp` calls `(this->*prototype)(...)`.
- **Why.** The Nix LLVM 22.1.8 `wasm32-unknown-linux-musl` target uses the
  generic Itanium C++ ABI. That ABI treats an odd member-pointer `ptr` as a
  vtable offset. On Wasm, `ptr` is a function-table index, so an odd index
  (`_image_prototype`, elem 7391) is dispatched through a vtable that does not
  exist. The result is "function signature mismatch".
- **When it fires.** At the first shader compile, when the GLSL builtins are
  initialised.
- **Fix.** A minimal Mesa patch,
  `tools/zink/patches/0001-glsl-builtin-image-memfnptr-wasm.patch`. Under
  `#if defined(__wasm__)` it picks one of the three known prototypes by
  member-pointer equality, which is ABI-safe, instead of calling through the
  pointer.
- **Why a Mesa patch is unavoidable.** No adapter can intercept a C++
  member-pointer call inside a Mesa translation unit.
- **Why not change the ABI.** The clean alternative is
  `-fc++-abi=webassembly`. It changes constructor/destructor `this`-return
  conventions, so it would mismatch the prebuilt libc++/libc++abi.
- **How the patch is applied.** `tools/zink/mesa-overrides.sh` copies the
  file from the pinned Mesa tree and patches the copy. It compiles the copy with
  the exact ninja command from `compile_commands.json` (depfile flags removed)
  and links the object ahead of the archives. The Mesa source and ninja trees
  stay unmodified. `tools/zink/link-wasm32.sh` and
  `tools/glgears/build-glgears.sh` now call it.
- **Implications:**
  - Any C++ in the guest built with this toolchain that calls through a
    non-virtual member-function pointer with an odd table index will trap.
    That includes **Firefox**, which uses the same toolchain. Audit it, or
    move the toolchain to a matching WebAssembly C++ ABI everywhere.
  - glgears softpipe (S1) probably avoided the trap only because of
    table-index parity luck in that link. The override now applies to glgears
    too.

### 1b. `vkCmdBindVertexBuffers2` (run 5, first `glDrawArrays`)

- **What happens.** Mesa 26 Zink
  (`zink_context.c: zink_bind_vertex_buffers_internal`) always calls
  `VKCTX(CmdBindVertexBuffers2)`, even without extended dynamic state.
- **Why it trapped.** The ICD returned NULL for that proc. Zink then filled the
  slot with its untyped `void(void)` `zink_stub_function_not_loaded`, and the
  typed call trapped.
- **This requirement was missing from the B0/B1 list.**
- **Fixes:**
  1. `zink.inc` adds `zink_bind_vertex_buffers2`, which forwards to the
     existing `bind_vertex_buffers`. It rejects dynamic strides and null slots,
     and logs generic buffers that have no host vertex buffer.
  2. `gen-zink-stubs.py` now emits a **typed** `zstub_` for every Vulkan proc
     the ICD does not implement: 550 stubs in total. Each logs `UNIMPL`.
     Command-buffer stubs invalidate the command buffer, VkResult stubs return
     `VK_ERROR_FEATURE_NOT_PRESENT`, and other procs return 0.
  - Together these mean Zink never installs its untyped stub. A missing proc
    now produces a trace line instead of a trap.

## 2. Current first-draw failure (run 6, clean, no trap)

`EGL init`, the ES2 context and the clear readback pass. Shader compile/link
passes (`linked=1`). The draw then fails cleanly. Errors, in order:

1. `set_layout REJECT binding=128 type=1 count=1 stages=0x10`. Zink puts its
   fragment-shader sampler (or its null descriptor) at binding 128 in its own
   set layout. The ICD's layout model rejects it, so `vkCreatePipelineLayout`
   fails.
2. As a result, `vkCreateGraphicsPipelines` fails. Mesa also warns about the
   missing `VK_EXT_depth_clip_enable`.
3. `UNIMPL`: `vkCmdSetViewport`, `SetScissor`, `SetStencilReference` x2,
   `SetBlendConstants`, `SetDepthBias`, `SetLineWidth`.
4. `bind_vertex_buffers2`: a generic buffer (usage 0x1ff) has no host vertex
   buffer.
5. `end_command REJECT state=4`, so `vkEndCommandBuffer` fails.
6. Readback is `DRAW gles2 FAIL inside=0,0,0,0 outside=0,0,0,0 glerr=0x0`.
7. `eglDestroyContext` then spins without end in `zink_context_destroy`. Run 7
   stack samples show it in that frame with no callees, which suggests an
   inlined loop. The guest kernel reports RCU stalls. This is not investigated
   further and may involve blocking waits (B2b).

## 3. Remaining blockers, in order

1. **Descriptor layouts.** Accept Zink's sparse binding numbers (128+), its
   per-stage set scheme, and `>=3` sets. Map them to the host's bind groups.
2. **Graphics pipelines from Zink SPIR-V.** Translator coverage for Zink's
   shaders. Report `depthClipEnable`, or accept the warning.
3. **Dynamic state.** Viewport/scissor are required. Stencil reference, blend
   constants, depth bias and line width can be no-ops when equal to the
   defaults.
4. **Generic (B2f) buffers.** These need host vertex/index/uniform backing and
   uploads at submit.
5. **Push constants.** Rewrite PushConstant to a Uniform at a reserved
   set/binding in the ICD's SPIR-V path, and execute `vkCmdPushConstants` as a
   UBO update. Not started.
6. **Transfer commands.** `vkCmdCopyBuffer`, `FillBuffer` and `UpdateBuffer`
   are not started.
7. **Teardown spin** in `zink_context_destroy`, plus blocking fence and
   timeline waits (B2b).
