# V1 vkgears: Vulkan glxgears on the guest ICD (2026-10-01)

Packet V1 of the 10-01 benchmark plan (softpipe GL vs Zink GL vs native Vulkan
gears). `vkgears` draws the classic glxgears scene in the wasm32 Linux guest with
plain Vulkan 1.1 through the static Khronos loader 1.3.231 and the guest ICD.
The ICD forwards to host WebGPU (NVIDIA recipe) or the WebGL2 fallback. Frames are
read back and presented with `XPutImage`, and the app prints glxgears-style FPS.
No commits were made by this packet.

## Files

- `web/linux/tests/vkgears/vkgears.c`: app (glBegin emulator around verbatim
  glxgears `gear()`, Vulkan setup/render, X11 present, FPS output).
- `web/linux/tests/vkgears/shaders/gears.{vert,frag}`: per-vertex lighting
  `color * (0.2 + max(dot(n, normalize(5,5,10)), 0))` (glxgears light).
- `web/linux/tests/vkgears/build.py`: derived from `tests/gputest-demo/build.py`;
  adds `--snapshot` (frozen ICD sources) and
  `-ffile-prefix-map=<out>=/vkgears-build` for reproducibility.
- `web/linux/tests/vkgears/gputest-init`, `gputest-waiter`: rdinit adapter and
  waiter (start after X0, then `exec /init`; rootfs `/init` unchanged).
- `tools/guest-rootfs/package-gputest-vkgears.py`: CPIO packager
  (`web/linux/gpu/gputest-vkgears.cpio` + `.json`).
- `web/linux/gputest.mjs`: `vkgears` in `GPUTEST_APPS`; cmdline flags
  `gputest.app=vkgears gputest.vkmode=<mode> [gputest.vksize=WxH]`.
- `web/linux/gputest.test.mjs`: vkgears assertions (7/7 tests pass).

## URL parameters

`?gputest=1&gputestapp=vkgears[&gpubackend=webgl][&vkmode=bench|present|nopresent][&vksize=WxH]`

- `vkmode` falls back to `glmode`, then `bench`.
- `vksize` must match `^[1-9]\d{0,3}x[1-9]\d{0,3}$` with each side at most 4096;
  otherwise it is dropped.
- `bench` runs 30 s present with `-info`, then 30 s `-nopresent`, then present
  until the page closes (3 attempts, 5 s apart).
- `&firefox=1` delays the start by 20 s, as the other gputest apps do.

## Scene and differences from glxgears

- Geometry is identical: three gears, 2640 vertices (1320+660+660), 24-byte
  stride. QUADS/QUAD_STRIP are triangulated; flat sections take the provoking
  vertex normal (GL last-vertex rule), and the inner cylinder is smooth.
- Transforms: same rotations/translations/frustum; converted to Vulkan clip
  space (y flip, z remap). One UBO with three 256-aligned regions (mvp,
  modelview, colour), three descriptor sets, three draws per pass.
- Differences:
  - `CULL_NONE` (glxgears enables back-face culling).
  - Depth is D32 (the ICD has no D24).
  - The render target is capped at 128x128 by the ICD (`maxImageDimension2D`),
    then nearest-neighbour upscaled to the 300x300 window on the CPU.
  - Every submit re-uploads all vertex and UBO data (the ICD uploads the
    coherent memory per submission).
- Backend detection: `maxVertexInputBindingStride == 252` means the WebGL2 host.

## Modes

- present: render pass, copy colour to a readback buffer, `vkQueueWaitIdle`,
  CPU upscale, `XPutImage`. This is the end-to-end frame rate.
- nopresent: render pass and `vkQueueWaitIdle` only, no readback. On WebGPU the
  host waits for `onSubmittedWorkDone`, so this is GPU completion. On WebGL2 the
  host only flushes, so this measures command issue, not completion.

Output: `VKGEARS_START`, `VKGEARS_READY`, glxgears `N frames in X seconds = Y FPS`,
`VKGEARS_FPS backend= device= fps= frames= seconds= present= size= render=`,
`VKGEARS_DONE ... avg_fps= status= reason=`.

change between frames. The WebGL gate's harness `adapter` field reports nvidia
because the runner queries `navigator.gpu` separately. The page log shows that
the session actually used `backend=webgl2` with ANGLE Intel UHD 620.

Context only, not a like-for-like comparison: S1 softpipe glgears at 300x300
(`/mnt/p6/build/glgears-s1-20261001/gate-softpipe-run2`) measured 88.5 FPS
present and 185.3 FPS nopresent. That run renders 5.5x more pixels in software;
vkgears is limited by per-frame IPC, re-upload and readback. The fair S2
comparison needs glgears at 128x128. The glgears waiter has no `-size`
passthrough yet, and this packet did not edit glgears, so that is deferred to S2.

## Failed run kept

`gate-webgpu-run1` failed. Present worked (57 FPS), but nopresent frame 2 hit
`VKGEARS_ERROR vulkan line=518 result=-3 call=vkEndCommandBuffer(cb)`. Cause: the
COLOR_ATTACHMENT->COLOR_ATTACHMENT barrier used between nopresent frames had
dstAccess WRITE only. The ICD requires READ|WRITE for that write-after-write
hazard. `color_barrier` was fixed, and build-run5/run6 were rebuilt.

The ICD returns `VK_ERROR_INITIALIZATION_FAILED` (-3) for invalid recording.
The app maps -3 to status 3 ("gpu lost") and skips teardown. For recording
errors that label is misleading.

## Reproducibility

- build-run5 and build-run6: `vkgears.wasm` 1,328,412 bytes, sha256
  `fc6e10d524ce9652943aef1346cdeac276324103f639ed2f2227ca02926f37dc` (identical).
- package-run5 and package-run6: `gputest-vkgears.cpio` 1,331,200 bytes, sha256
  `338e88c1dc067468feb6a5ae2ebe8de69a6084eac639842f218064d28bebd7c6`
  (identical, installed in `web/linux/gpu/`).
- build-run1/run2 differed by 3 bytes because the loader `assert` `__FILE__`
  strings embedded the run directory. `-ffile-prefix-map` fixed this.
- The ICD sources are a frozen snapshot of HEAD `f9c1ce7`
  (`/mnt/p6/build/vkgears-v1-20261001/icd-snapshot`). This isolates the build
  from the concurrent B2f edits in `web/linux/tests/guest-vulkan/`.

## Open issues

- The 128x128 render cap. Raising the ICD image cap (caps packet) lets vkgears
  render at window size (`vksize`/`-size` is already wired).
- Every frame re-uploads all vertex and UBO data. The ICD should skip
  unchanged buffers.
- The -3 to "gpu lost" status mapping is misleading.
- WebGL2 nopresent measures command issue, not GPU completion.
- S2 needs a glgears waiter `-size` passthrough for a matched 128x128 run.
