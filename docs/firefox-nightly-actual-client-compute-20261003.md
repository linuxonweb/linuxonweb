# Actual current Rust-client compute benchmark, 2026-10-03

The standalone Linux/Wasm application passes actual Nightly159 Rust-client compute, queue completion and mapped-readback correctness on hardware NVIDIA WebGPU and host SwiftShader WebGPU. Four sequential ABBA arms measure **101.609666 completed operations/s on NVIDIA versus 135.151877 on SwiftShader: 0.7518183896561359×**. Software is faster for this workload; this result establishes no hardware speedup. The earlier actual guest Vulkan-loader render/readback result of 18.1778× is a separate workload and remains unchanged.

Each arm executes five warmups and 30 measured frames with identical sources, native module, CPIO, Rust executor, runtime/request hashes and six observed host/browser/guest CPUs. The native client is linked from the accepted independent archived `libgkrust.a`; it uses current `wgpu_client_*` shader, asynchronous pipeline, compute-pass, submission and map exports. Queued messages come from the real client serializer, and actual returned bytes enter `wgpu_client_receive_server_message`. Current protocol types are derived from pinned Nightly159 sources and wgpu revision `4f4dc63098fae64a0e6d1d3dc6f4f328da8fd5c8`. The browser-host executor uses genuine Rust wgpu 30.0.1.

Each frame processes 2,048 u32 words in an 8,192-byte storage buffer, dispatches 32 workgroups of 64 invocations, and runs 1,024 wrapping integer rounds per word: `x = (x ^ (x >> 13)) * 1664525 + 1013904223`. Inputs vary by frame; all mapped words are checked against a CPU reference. The four arms retain all 140 raw samples, 286,720 word checks with zero failures, 140 actual map and work-done callbacks, four shader and asynchronous-pipeline callbacks, and 1,852 actual serialized messages. Map bytes are published into the isolated harness's mapped storage before the actual client callback.

Timing uses guest `CLOCK_MONOTONIC` immediately before real queue write and native encoding through the actual map callback, before CPU verification. It includes encoding, hostcall transport, real Rust wgpu compute, copy, submitted-work completion and map publication/callback. It excludes shader/pipeline compilation, CPU input/reference generation, verification and unmap. Throughput is pooled as 60 operations divided by the summed measured duration of the two matching arms. It measures completed compute/upload/copy/readback/transport operations, with no GPU-kernel or presentation-FPS attribution. The final hardware arm's retained load-after reading is `3.29 0.91 1.41`; the evidence does not infer its cause or attribute performance to that reading.

The isolated executor matches current `server.rs` semantics: asynchronous compute-pipeline creation returns a success or validation-error response; synchronous creation returns no response. This candidate correction changes no production executor. WebGL has no compute stage; its earlier genuine copy/map acceptance is separate. Actual current-client serialization/callback correctness does not accept Firefox DOM promises, IPC shared-memory publication, adapter/device completeness, compositor/rendering or full Nightly GPU.
