## What the ICD adapter needed (all under `GUEST_VK_ZINK`, no Mesa change)

### Shaders (`zink_remap_spirv`, `zink_rewrite_ubos` in `zink.inc`)

- **Bindings.** Binding decorations are remapped to host slots:
  - 0..11 stay as they are;
  - Zink's fragment sampler slots 128..131 become 12..15;
  - anything else is rejected with a trace.
- **Push constants.** Zink declares a `gfx_pushconst` block in every shader. It
  is dropped when unused; any real use is rejected.
- **GLES2 `gl_FragColor`.** Zink lowers it to stores into all of
  `gl_FragData[0..7]`. The fragment outputs at Location >= 1 are dropped
  together with their stores. The host has one colour attachment.
- **Uniform blocks.**
  - Zink's GL uniform block is `[1] x struct { uint[N] }`, accessed per word
    and bitcast to float.
  - It is rewritten to the host translator's
    `struct { vec4<f32>[ceil(N/4)] }` with stride 16.
  - Each word access becomes `OpAccessChain f32 [k/4][k%4]` + `OpLoad f32` +
    `OpBitcast uint`. Dynamic indices use a shift and a mask.
  - Any other use of the uniform pointer is rejected.
- **Debug dump.** `vkCreateShaderModule` also dumps SPIR-V when
  `GUEST_VK_TRACE` is set. Zink creates shader modules separately from
  pipelines.

### Pipelines and commands

- **Pipeline create info.** Zink zero-initialises it, so:
  - `basePipelineIndex` 0 without DERIVATIVE is treated as -1;
  - `frontFace` is normalised to CCW when `cullMode` is NONE, where it has no
    effect.
- **Dynamic state.** Viewport and scissor are recorded per draw. A
  dynamic-state pipeline needs both before its draw.
- **Generic vertex buffers.** Buffers with VERTEX usage, suballocated by Zink,
  are staged at submit through a lazily allocated 8 x 64 KiB host ring.
  - Each draw uploads only the bytes it reads.
  - Uniform buffers use the same ring.
- **Push UBOs.** Zink's per-stage push UBO bindings for geometry, tessellation
  and compute stages are omitted from host pipelines and draws.
- **Descriptor update templates.** Up to 8 entries are supported.
- **Resource table.** `MAX_RES` is 1024 under Zink, because Zink allocates
  descriptor sets 10 and then 90 at a time and each set is one resource. The
  zinkcaps test link now starts with 8 MiB of initial memory.
- **`invalid_command` trace.** When tracing is enabled, `invalid_command` now
  reports its caller (`invalid_command <func>:<line>`). Rejected
  copy_buffer_to_image and image barriers print their parameters.

### Host (`guest-vulkan-graphics/renderer.mjs`)

- `validatePipelineDescriptor` now accepts a vertex format that supplies fewer
  components than the shader input reads.
- Vulkan, WebGPU and WebGL2 all fill the missing components from `(0,0,0,1)`.
- GL attributes always reach Zink as vec4.

## Not done / next

- **Texturing a Zink image (`EGLPROBE_TEXTURE=1`).** It fails.
  - Zink creates every colour image with COLOR_ATTACHMENT + SAMPLED usage. The
    ICD makes such images host render targets only (`sampled=0`).
  - The texture upload (`vkCmdCopyBufferToImage` from a generic buffer) and the
    TRANSFER_DST -> SHADER_READ barrier are therefore rejected.
  - Fix:
    - host targets with `TEXTURE_BINDING | COPY_DST` (WebGPU), with the WebGL
      equivalent;
    - copies from generic buffers;
    - sampled views of target images.
  - The probe now draws untextured by default. glgears does not texture.
- **Push constants** are still dropped only when unused.
- **Index buffers, strip/fan topologies, depth with Zink's formats (Z24S8) and
  blocking waits (B2b)** are still needed before glgears on Zink.
- **Risk: float-load/bitcast UBO reads.** A host that flushes denormals on f32
  loads could alter integer uniforms whose bit pattern is a denormal float.
  WebGPU/WGSL and GLSL ES 3.0 loads are bit-preserving in practice, but this is
  not guaranteed.
- **Risk: bound UBO range.** The rewritten block size is `ceil(N/4)*16`. It can
  exceed the bound range when N is not a multiple of 4. Zink's uniform block
  sizes have been multiples of 16 so far.
