## Changes (all adapter code in `web/linux/tests/`, no upstream edits)

Everything new is gated by `GUEST_VK_ZINK`. Only the zinkcaps build and the
gate-B link define it, so the direct, exhaustion and other suites see
unchanged behaviour (32-entry resource table, no BGRA).

- `guest-vulkan/icd.c`
  - `color_format()` also accepts `VK_FORMAT_B8G8R8A8_UNORM`, so format
    properties and image format properties report BGRA8 the same as RGBA8
    (colour attachment, blend, sampled, transfer src/dst; maxExtent 128).
  - SRGB stays unsupported (`FORMAT_NOT_SUPPORTED`, feature flags 0).
  - `maxImageDimension1D = 128`.
  - `independentBlend` is advertised and accepted when graphics is
    supported. Mesa ES2 requires `EXT_blend_equation_separate`, which Zink
    derives from independentBlend.
- `guest-vulkan/transfer.inc`
  - Resource table: `MAX_RES` is 128 under ZINK (32 otherwise).
  - Each image records `bgra`. The host always stores RGBA with logical
    channels; R and B are swapped only on guest-visible bytes:
    - image-to-buffer readback (op 3);
    - texture upload.
  - The view format must match the image format, so an RGBA view of a BGRA
    image is refused.
  - `ZINK_TRACE` reject lines on the create_image, create_buffer and
    allocate_memory paths.
- `guest-vulkan/texture.inc`: swaps R and B on upload of a BGRA image.
- `guest-vulkan/graphics.inc`, `graphics-commands.inc`, `zink.inc`: views,
  render passes, framebuffers, dynamic-rendering pipeline formats and
  `vkCmdBeginRendering` accept either colour format.
- `guest-vulkan{,-compute,-loader,-graphics}/storage.py`: task root added to
  the storage guards.
- `guest-vulkan-zinkcaps/client.c`, `guest.html`: BGRA block (round 11),
  `maxImageDimension1D == 128` and `independentBlend == VK_TRUE` checks.
  Expected host counters are now 11 passes, 14 draws, 11 uploads,
  6 uniform uploads and 11 readbacks.

## BGRA8 pixels (zinkcaps round 11, both backends)

16x16 B8G8R8A8_UNORM image, dynamic rendering, `LOAD_OP_CLEAR` to
(0,0,1,1) blue, then a red quad (uniform offset 0.25,0.25) drawn with the
BGRA pipeline. Readback with `vkCmdCopyImageToBuffer`, then an exact
comparison of all 1024 bytes plus a 32-byte sentinel tail:

- Blue background: bytes `255,0,0,255` (B,G,R,A).
- Red quad, x and y in [6,14): bytes `0,0,255,255`.

Output: `GUEST_VK_ZINKCAPS_PIXELS_PASS round=11 width=16 height=16 exact=1024 tail=32`,
then `GUEST_VK_ZINKCAPS_BGRA_PASS frames=1 refused=2 dim1d=128 independent_blend=1 srgb=0`.

The two refusals are an SRGB image creation and an RGBA view of a BGRA
image. Sampling a BGRA texture in a shader has no test yet: zinkcaps has no
sampler shader, so the texture-upload swap is implemented but unexercised.

What happens: the screen and the configs come up. During context creation,
Zink creates its small dummy/null buffers with every usage bit set
(`0x1ff` = transfer src/dst, uniform/storage texel, uniform, storage, index,
vertex, indirect). The ICD accepts only one bounded role per buffer, so it
refuses. gl-core and gles3 return BAD_MATCH because the device cannot reach
GL 3.x / ES 3.0 (see the limits below).

## Zink GL limits vs minimums

| quantity | Zink on this ICD | ES 2.0 min | ES 3.0 / WebGL2 min |
|---|---|---|---|
| GL_MAX_TEXTURE_SIZE (`MIN3(dim1D, dim2D, 16384)`) | 128 | 64 | 2048 |
| GL_MAX_DRAW_BUFFERS (max_rt) | 1 | 1 | 4 |
| GLSL | 4.60 reported by caps; context version bounded by features | 1.00 | 3.00 |
| reachable context | ES 2.0 / GL 2.1 compat at best | ok | no (0x3009) |

Before B2e, dim1D was 0, which made Zink's max texture size 0 (unusable).
128 meets ES 2.0 but not WebGL 1 in practice: browsers expect at least 2048
for WebGL1 content, and WebGL2 requires 2048. Raising it needs host texture
limits above 128 (the WebGPU/WebGL2 host protocol caps textures, depth and
render targets at 128).

## Next blockers, in order

1. **Universal buffer usage.** Zink requests usage `0x1ff` on every buffer,
   including size-4 dummies. The ICD needs a generic buffer model: keep the
   guest-side bytes and lazily create or upload per-role host buffers
   (vertex, index, uniform, storage, transfer) at submit.
2. **Suballocation and memory.** Zink suballocates: nonzero bind offsets,
   allocations above 64 KiB, several buffers or images per VkDeviceMemory,
   and a larger heap than the current 1 MiB.
3. Likely after that:
   - Zink creates images with broad usage sets, so image usage checks must
     allow them.
   - Zink uses multiple command pools/buffers per context.
   - The gate-B link snapshot still uses MAX_RES 32 (`zinkb/icd/src`
     predates the change); re-snapshot before the next link.
   - Barrier strictness: Zink emits sync2-style or generic barriers.
   - Push constants (B2c): Zink's draw path uses them, so a draw cannot work
     without them.
   - BGRA texture sampling: implemented, but no test covers it.
4. Raise the host limit of 128 for texture and render-target sizes; this is
   required for WebGL-class GL_MAX_TEXTURE_SIZE.
